# 后续实施计划

更新：2026-11-03。用户已授权自主安排、分配任务和执行编码。本计划组织已确认需求，不增加架构替换、依赖或正式发版授权；当前状态见 [PROJECT_STATUS.md](PROJECT_STATUS.md)。

## 执行方式

- 主线负责桌面显示正确性与整体验收；并行工作可做导入审查、标注领域模型/测试和进度维护。
- 每个增量完成实现、对应验证和独立评审后，按个人仓库约定在 `main` 单独提交并推送，跟进 CI 与 Pages；提交使用英文 Conventional Commits，并保留 Codex co-author。
- 先核对工作树归属；既有 7 个导入相关改动需要独立收敛，不夹带到渲染或 UI 提交。新功能不覆盖他人改动。
- 候选修复若实际回归失败，不以构建通过代替修复，不留下叠加补丁。记录排除的假设与下一条可验证路径。
- 浏览器访问受限时，继续不依赖它的代码和桌面验证；Web 验收保持未通过，不用其他通道绕过审批。

## D1 的排查顺序

1. 固定已复现的系统、应用构建、样本、布局/主题切换序列，保存操作步骤与实际失败证据。
2. 用最小页面逐层引入画布合成、CS3D 正交视口、布局切换和应用覆盖层，区分故障在哪一层首次出现；简化场景正常不等于底层已排除。
3. 根据证据修改对应生命周期、尺寸或合成边界。保持当前锁定版本；若必须升级或替换架构，先给出复现和影响，不盲目升级。
4. 在完整应用重复验收；首次打开正常、单次截图正常或 `whenIdle` 返回都不能作为关闭依据。
5. 记录未覆盖平台。macOS 修复通过不等于 Windows/Linux 也已验证。

## 每个增量的交付清单

- 对应源文件、类型、调用方与错误路径一起修改，维持现有 Ports & Adapters 边界和本地处理约束。
- 先读取实际项目脚本；通常运行 `pnpm typecheck`、`pnpm lint`、受影响测试与 Web 构建。桌面相关改动补 Rust 检查和 Tauri 打包/实机流程。
- 数值与状态逻辑使用单元/集成测试，关键数值做变异自检；界面用实际浏览流程验证。遵守 GEMINI 的 e2e 范围与总数限制，不用快照替代物理正确性。
- 对范围很小的文案/CSS 修改，执行适当检查与可见结果验证，不新增只复述实现的测试。
- 独立评审按发现逐条处理，新增报告保留历史。提交后确认远端分支包含提交、必需检查通过、Pages 对应版本正确。
- 更新当前状态与详细功能计划；只有代码和验收均完成才改为已交付，模型/接口/菜单占位保持在制。

## 当前不会自动扩大执行的范围

不创建 Release/标签，不换渲染架构，不升级锁定 CS3D，不启用默认患者缓存，不修改脱敏业务契约，不引入新依赖，不将本地真实数据上传仓库。这些边界不阻止既有架构内的普通实现、验证、提交与推送。
