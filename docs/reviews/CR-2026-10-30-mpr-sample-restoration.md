# 修正脑部示例导致的多视口体验退化

日期：2026-10-30。

## 原因与证据

2×2 / 1+3 布局、MPR、十字准星与翻层联动没有删除。`WorkspaceToolbar.tsx` 仅在 `planVolumeDownsample(meta).ok` 且渲染器 `supportsVolume` 为真时显示布局按钮；`viewer-store.ts` 遇到不合格数据会退回 1×1。

上次 `90b1264` 把默认脑部入口换为单层矢状面，真实规划结果为 `INSUFFICIENT_SLICES`，因此隐藏了布局入口。这次选择没有保留原有演示能力，属于默认体验退化。

进一步实测：旧 `brain-mr` 虽有 36 帧，却被规划器拒绝为 `INVALID_SPACING`，提示第 2 层不在均匀网格上。不能简单建议切回旧序列，也不能关闭几何校验假装重建正确。诊断脚本和输出位于 `/private/tmp/odv-mpr-check-20261030/verify.test.ts`。

## 修正

- 同一公开 ICBM152 T1 模板导出 193 层完整连续轴位，矩阵 193×229，1 mm 等距。保留源 int16 体素及缩放，不插值、不伪造层位置。LPS 原点 `[-96,-96,-78]`，方向为单位阵，全部文件哈希写入 `provenance.json`。
- 欢迎页仍使用原中线人头预览；同一数据集保留单层矢状面参考图，首次导入默认选择 193 层序列。原 URL `?sample=brain-head-mr` 不变，需刷新或重新载入以更新内存中的旧样本。
- 卡片下常显 MR 的 193 层 / MPR 能力和 CT 单层限制；右栏「空间重建」说明如何进入 2×2 / 1+3，不可用时可展开真实原因。
- 复用原来的 MPR 构建、视口、十字准星和翻层代码，不修改渲染架构、几何校验、依赖、CI 或构建脚本。没有更改原始 36 帧 MR 或 CT。

## 验证

1. 导入 194 个文件后，两条序列依次为 193 层连续轴位和 1 层矢状参考，默认序列可通过现有几何规划。
2. 源体素可在矢状面与轴位间对应；连续体积的尺寸、原点、方向和层距正确。
3. 通过现有 `buildVolumeFromSeries` 构建 128 上限的降采样体积，尺寸 96×114×96、2 mm、原点半体素偏移正确，源八体素均值重标定后为 60.1514433，对应固定窗口输出 155。
4. 准星中心、MPR 轴向移动与原始 Stack 翻层移动的世界坐标一致；2×2 / 1+3 不再被状态管理退回 1×1。
