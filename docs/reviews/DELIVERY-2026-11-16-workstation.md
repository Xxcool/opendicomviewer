# 影像工作站交付验收 · 2026-11-16

本次将本地导入、切换视图和保存结果连成一个工作流程。继续使用现有 React、Cornerstone3D 和 Tauri 架构。浏览器和桌面端复用同一套序列识别与结果编码逻辑。

| 场景 | 验证步骤与结果 |
| --- | --- |
| 导入与首屏 | 首页可选择文件、文件夹、ZIP 和教学示例。生产包首屏加载不包含 Cornerstone3D。导入期间保留旧会话，首个可用序列准备好后再替换。样例下载最多六个并发请求，单请求包含响应体读取的超时为 20 秒，瞬态失败重试一次。 |
| 小屏与降级 | 在 390 像素宽的浏览器视口打开影像，画布宽 390 像素，两侧面板可收起。单层影像菜单显示无法进入 3D 的原因。 |
| 3D | 载入项目的 193 层 ICBM 教学数据，在生产 Web 构建及本机 macOS 应用中打开灰度体渲染并旋转。浏览器画布为 1056 × 542，旋转 15° 后超过 11.8 万像素发生变化。 |
| 4D | 导入下列公开 Philips fMRI 的 27 个原始实例。识别为 3 个时相，每个时相 9 层。浏览器中 MPR 播放到第 3 相，另在 3D 中切相并旋转。分组以时间标识和逐相一致的空间几何为依据。 |
| 结果交换 | 浏览器绘制 29.56 mm 测距，分别导出 Enhanced SR 与 GSPS，再读回并匹配原始实例。用独立的 DICOM IOD 校验器按 2025e 版校验两份导出文件。对 ZIP 中对应原始实例进行了字节一致性检查。 |
| 自动化与构建 | 426 项 Vitest、14 项 Rust 测试、类型检查、lint、Web 生产构建和本机 macOS 桌面应用构建通过。 |

复验 4D 时，将该样本目录中的 DICOM 文件导入同一会话，进入 MPR 并逐相查看，再切换至 3D。保留原始实例及时间标签。[Philips Magdeburg fMRI 数据](https://github.com/neurolabusc/dcm_qa_philips/tree/1a851fb2e9cf9cc2432fb0264e724da29c4bcf51/In/Magdeburg_2014/fmri)

## 稳定版仍需验证的范围

- 4D 当前覆盖带明确时相标识的经典单帧 MR。增强多帧、心动和多回波等采集需要各自的识别契约与样本验证。
- 3D 当前提供灰度体渲染。设备显存差异、长时间使用和大序列运行表现待目标设备验证。
- SR 当前交换单源帧的毫米测距。完整 TID 1500 报告及第三方 PACS/工作站互操作待验。GSPS 支持图形预览，完整可编辑标注可用项目 JSON 保存。
- Windows 安装与签名、目标浏览器矩阵和原生 SR/GSPS 保存对话框仍待实机验收。当前验收不覆盖临床诊断用途。
