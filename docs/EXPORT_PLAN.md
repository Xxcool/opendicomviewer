# 导出功能计划

日期：2026-11-01。状态：规划，尚无用户可用导出链路。先完成桌面显示正确性和真实数据导入验收，再实施。

## 格式与交付顺序

| 增量 | 格式 | 用途与范围 |
| --- | --- | --- |
| A | PNG | 默认无损图像；当前影像或当前多视口布局，支持包含/隐藏标注与信息叠加 |
| A | JPEG | 分享用的较小图片，可选质量；有损，不作为测量数据存档 |
| B，依赖标注模型与恢复链路 | JSON | 版本化标注/测量数据；重新选择匹配原始影像后可恢复编辑，不内嵌原始像素 |
| B，依赖测量验收 | CSV | 测量结果表，可用 Excel 打开；类型、数值、单位、影像/帧引用和有效性说明；不支持从表格恢复几何标注 |
| C | PDF | 选定图片、标注、测量摘要及用途声明；导出材料，不生成自动临床诊断结论 |
| C | ZIP | 将用户选择的原始 DICOM 文件原样打包；也可打包选定图片与 JSON/CSV。两种包类型须明确区分 |

原始 DICOM 打包保持字节和目录引用关系，不把截图改扩展名当成 DICOM，不把原样复制称为脱敏导出。脱敏 DICOM 是另一个依赖 PS3.15、UID 映射及烧录信息复核的增量。

医院系统互操作另行规划 DICOM SR（结构化测量）与 GSPS（灰阶图像呈现状态及适用的图形标注）。SEG 用于像素分割结果，应随未来分割能力规划，不将其当作所有箭头/角度标注的通用格式。标准依据：[TID 1500 Measurement Report](https://dicom.nema.org/medical/dicom/2026c/output/chtml/part16/chapter_A.html#sect_TID_1500)、[Segmentation IOD](https://dicom.nema.org/medical/dicom/final/sup243_ft_LabelMapSeg.pdf)。互操作格式必须经过独立查看器读回验证，再声明支持。

## 交互与正确性验收

- 导出入口统一提供范围、格式、文件名、分辨率、标注/标尺/身份信息叠加选项与预览；默认不额外叠加姓名和编号。源像素内已有的身份信息不因关闭叠加而消失，不能宣称自动脱敏。
- 明确区分当前视图截图与源矩阵渲染图；保存窗宽窗位、方向和标注的一致状态。等待画面稳定仍须验证最终画面，不能仅凭 `whenIdle` 返回认定正确，尤其在当前桌面重绘缺陷未修复时。
- 多视口、MPR 导出在布局及朝向正确性通过后开放；降采样体积标明仅用于显示与定位。
- JSON 须包含 schema 版本、源序列/SOP/多帧帧号、坐标系与单位、控制点、文本、稳定标注 ID、测量有效性及必要计算来源。当前 MeasurementRecord 尚不足以直接充当稳定交换格式，先补跨帧与坐标语义，避免直接导出内部状态。
- CSV 数值源自通过物理校验的测量模型；未校准、缺失间距或不满足 HU 换算条件时输出不可用及原因，不输出伪毫米/伪 HU。防止文本字段被电子表格当公式执行。
- Web 本地保存与 Tauri 原生保存对话框分别验收；覆盖用户取消、同名文件、权限/磁盘不足、批量进度、中断与失败清单。原文件保持不变，覆盖已有目标须明确确认。
- PNG 检查像素尺寸与叠加位置；JSON 做保存—恢复—编辑往返；CSV 与测量模型对照；PDF 检查分页、字体与图片完整性；原始 DICOM ZIP 解包后逐文件校验字节一致性和 DICOMDIR 引用。
