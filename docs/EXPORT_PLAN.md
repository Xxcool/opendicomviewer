# 导出功能计划

更新：2026-11-09。版本化标注 JSON 保存恢复、PNG 预览及桌面原生保存、原始 DICOM 导出已接入；原生保存及193实例导出再导入已实测，Web 下载实现仍待界面验收。SR/GSPS 待实施。桌面 MPR 已知重绘问题单列跟踪。原始导出的平台/来源边界见[交付记录](reviews/DELIVERY-2026-11-08-original-export.md)。

本次根据用户补充，主范围调整为 **PNG、DICOM、DICOM SR、DICOM GSPS**。参考医院与 DicomVisionClient 的使用场景，按本项目数据与能力独立设计；菜单存在不等于读写与互操作已验收。

## 格式分工

| 格式 | 优先级 | 保存内容 | 恢复边界 |
| --- | --- | --- | --- |
| PNG | 主要 | 当前影像或当前布局的无损显示图；可包含备注、标注、测量值 | 叠加内容成为图像像素，不能据此恢复可编辑标注或原始灰度 |
| DICOM 影像 | 必需 | 当前原始影像文件或当前序列的原始 DICOM 文件 | 原图保持不变；新增备注与测量另存 SR/GSPS，不能假定复制原图就包含新结果 |
| DICOM SR | 必需，依赖测量与备注模型 | 结构化测量值、单位、测量部位/方法等适用语义、备注及所引用影像/帧/区域 | 在支持所用 SR 模板的软件中读取；本项目须验收读回和标注模型恢复，第三方编辑能力另测 |
| DICOM GSPS | 必需，先限支持的二维灰阶影像 | 适用的图形/文字标注、显示区域与窗宽窗位等呈现状态，引用原图而不改像素 | 在支持相应呈现状态的软件中恢复展示；不代替 SR 的结构化数值语义 |
| JPEG | 可选，放在“导出图片”的格式选择中 | 便于分享的有损图片，可选择质量 | 用途同显示图，不作为原始影像和可编辑测量存档 |
| JSON | 已有显式保存与 v1 恢复入口 | 版本化标注与会话数据，不内嵌原始像素 | 恢复时核对原始序列/SOP/帧与测距，支持继续编辑，不作为医院互操作的主要格式 |

SR 以选定的 TID 1500 Measurement Report 及适用测量组为设计基线，实施前逐工具明确模板、编码与单位映射。[DICOM TID 1500](https://dicom.nema.org/medical/dicom/current/output/chtml/part16/chapter_A.html#sect_TID_1500)

GSPS 保存所引用影像的呈现状态，涵盖适用的图形、文字和灰度变换；支持范围要按 SOP 类、工具及帧引用明确声明。[DICOM GSPS IOD](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_A.33.html)

CSV/PDF 留作后续按实际需求增加的统计或汇总材料，不占用主导出菜单。ZIP 是多文件打包容器，不作为影像语义格式单列。SEG 随未来像素分割能力规划。

## “带备注与测量”的导出方式

- **分享一张图**：PNG，按需包含文字、箭头、轮廓和测量标签；JPEG 作为可选另存格式。
- **保存原始影像**：单个 DICOM 原文件，或当前序列的原始文件集合。原样复制不宣称脱敏。
- **保存测量与备注**：SR 引用原始影像和适用区域/坐标，保存语义及数值；GSPS 保存适用的文字、图形和显示效果。两类对象由同一标注模型、同一导出快照产生。
- **一次带走影像和结果**：“影像 + 备注/测量”组合导出，包含原始 DICOM 与实际需要的 SR、GSPS；多文件可打包 ZIP。也允许单独导出结果对象，并说明还需对应源影像。
- 如果以后需要将标注直接写进像素的 DICOM，作为明确命名的派生图像/Secondary Capture 增量，创建新的 SOP Instance UID 并记录来源；不覆盖原始 CT/MR 或将截图伪装为原始断层。

## 交付顺序

1. 先完成单视口源帧、标注保存与导入完整性验收，再交付 PNG 与原始 DICOM 的当前文件/当前序列导出；不等待桌面 MPR 重绘问题关闭。
2. 标注/测量具备选中、编辑、删除、撤销及保存恢复后，交付 SR、GSPS 的限定工具集，作为必要交付范围，不再仅列为遥远互操作设想。
3. SR/GSPS 生成、标准检查、独立查看器读入与本项目读回均通过后，再声明对应格式和工具支持；补齐组合导出。JPEG 可在图片导出增量内按需求加入。
4. CSV/PDF、脱敏 DICOM、派生图像 DICOM 与 SEG 分开排期，不扩大首轮范围。

## 交互与正确性验收

- 按格式提供选项：图片选择当前视图/布局、分辨率与叠加内容；DICOM 选择当前文件/当前序列；SR/GSPS 选择当前影像或相应范围内的标注。原始 DICOM 不提供会悄悄改变像素的“截图分辨率”选项。
- 图片导出默认不额外叠加姓名与编号，提供预览。源像素内已有的烧录信息不因关闭叠加而消失，不能宣称自动脱敏；脱敏导出另按 PS3.15、UID 映射及人工复核验收。
- 原始 DICOM 含多帧时，“当前文件”保存完整 SOP 实例与全部帧；单帧显示图另走图片导出。提取新单帧 DICOM 须另做派生与功能组处理，不能直接裁掉原文件其他帧。
- 标注模型先补源序列/SOP/多帧帧号、坐标系与单位、控制点、文字、稳定标注 ID、测量有效性及计算来源。现有 MeasurementRecord 不能直接当稳定交换格式。
- 箭头、文字、直线、矩形、椭圆、角度/Cobb 角和自由轮廓逐工具建立 SR/GSPS 映射表；未支持的类型明确说明，不静默丢弃，也不把 GSPS 上的数值文字当成完整结构化测量。
- 删除后的标注不导出；撤销删除后恢复。导出冻结同一版本，确保 SR 与 GSPS 不出现数值、文字、几何不一致；空结果不产生虚假的测量对象。
- SR 数值必须来自通过物理校验的测量模型，验证单位、灰度换算和引用关系。未校准定位像、缺失间距或不满足 HU 换算条件时，不输出伪毫米/伪 HU；仍可保存适用的文字和图形。
- 保留源图 UID/帧引用；新生成的 SR/GSPS 使用新的 SOP Instance UID、适当 SOP 类及系列信息。对多帧引用、旋转/翻转、各向异性间距和中文备注分别验证。观察者/设备信息如实填写，不把软件或默认用户伪称为医生。
- GSPS 先限 MONOCHROME1/MONOCHROME2；不承诺彩色图像。若一组影像的 Modality LUT 逐帧变化，不能按普通 GSPS 静默导出，须明确说明当前不支持或另行实现适用对象。
- 单独 SR/GSPS 与组合包分别验证引用完整性。组合包须包含所有依赖源图，或明确报告不能提供的依赖，不能把悬空引用作为完整成功。
- PNG/JPEG 核对窗宽窗位、方向、尺寸和标注位置；等待画面稳定须检查最终结果，不能仅凭 whenIdle 返回认定正确。MPR/多视口导出须先通过朝向与绘制验收；不把仅用于显示的降采样体积当测量真源。
- SR/GSPS 做标准验证、独立查看器读入和本项目读回；逐项比对数值、单位、图形、备注、帧归属和显示状态，第三方不能编辑的内容需如实说明。
- 原始 DICOM 导出逐文件校验字节一致性，必要时验证 DICOMDIR 引用。Web 保存与 Tauri 原生保存分别覆盖取消、同名目标确认、权限/磁盘不足、批量进度、中断和失败清单。原文件保持不变。

## 当前保存边界

JSON 使用冻结快照；只有原生写入成功且会话未继续修改时才清除未保存状态。Web 发起下载不代表已落盘，需用户明确确认；取消或失败保留原会话。浏览器刷新/关闭、桌面窗口关闭及应用退出分别验收，结果见[本轮记录](reviews/DELIVERY-2026-11-04-tools-ui.md)。不自动缓存患者影像，不修改原始 DICOM；JSON 恢复另见本轮恢复记录；SR/GSPS 与图片导出不能由此推定完成。
