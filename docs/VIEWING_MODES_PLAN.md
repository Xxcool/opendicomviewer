# 影像浏览模式范围与路线

更新：2026-11-04。状态：产品与验收规划；不代表以下能力全部已实现。

## 目标与当前状态

| 模式 | 用户用途 | 数据前提 | 当前状态 |
| --- | --- | --- | --- |
| 2D 原始影像 | 单张/序列浏览、调窗、缩放、翻页、独立分屏、备注与测量 | 可解码的像素；毫米/HU 测量还需可靠标定与灰度语义 | 浏览已实现；单视口已接入测距、箭头与文字，ROI/HU/角度及分屏测量待实现 |
| MPR 多平面重建 | 从同一体积查看横断、冠状、矢状及后续斜面，联动定位 | 有效的空间几何、可构建体积；定位像/普通 SC 不适用 | 已有降采样三向与布局联动；桌面呈现和布局切换验收未闭环 |
| 3D 体绘制 | 旋转观察体积形态，选择骨/软组织等适用的显示预设、透明度与裁剪 | 有效三维体积及足够 GPU/内存能力 | 未实现，架构已有后续规划 |
| 2D 逐帧播放 / Cine | 单视口或独立分屏活动视口自动翻帧、暂停、速度及循环控制 | 可浏览的二维帧序列；当前 fps 为用户设置的播放速度 | 已实现控制器与界面，实际交互验收见本轮记录；尚无采集时间轴建模，不代表真实时间回放或 4D |
| 4D 动态体积 | 在多个三维时相间切换或播放，并在所选时相查看 MPR/3D | 真正的三维空间加时间维；每个时相各自有可用体积 | 未实现，需要新增时间维数据建模与真实样本验收 |

MPR 使用三维数据产生二维截面，不能拿三视图或四格布局冒充 3D 体绘制；也不能把“把切片从头播放到尾”宣传为 4D。单层定位像支持二维浏览，不能由软件凭空生成缺失的空间或时间信息。

标准依据：DICOM 通过维度组织、帧内容及适用的时间属性区分空间位置和时相；例如 fMRI 的 Temporal Position Index 区分不同时间体积。不能只凭帧数、文件名或 InstanceNumber 推测时间维。[DICOM Common Functional Group Macros](https://dicom.nema.org/medical/dicom/2026c/output/chtml/part03/sect_C.7.6.16.2.html)

当前 Cine 等待上一帧提交后再安排下一帧，遇到失败暂停并提示；切会话、布局、活动格、首页、模态或外部输入时停止播放。完整 GUI 结果与边界见[本轮记录](reviews/DELIVERY-2026-11-04-tools-ui.md)。

## 推进顺序

1. 在原始 Stack 上推进工具、播放与真实 DICOM、ZIP 导入验收。桌面 MPR 重绘问题单列跟踪，不阻塞已具备可靠坐标与像素链路的 Stack 功能。
2. 收尾已接入的单视口标注与二维播放验收，继续完成 ROI/HU、角度、保存恢复及 PNG、原始 DICOM、SR/GSPS 导出闭环；不以 Cine 替代 4D。
3. 在既有体积通路上增加基础 3D 体绘制；再按需要安排厚层投影等能力，逐项声明支持范围。遵守现有降采样显示路径与设备预算，不以低精度显示体积计算测量结果。
4. 为 4D 增加按时间、空间和其他采集维度组织的数据模型，选择明确支持的 SOP/采集类型，使用带真实时相的样本逐步交付。不能将时间帧与空间切片直接混排构建一个假体积。

## 交互与验收边界

- 模式入口按当前序列及设备实际能力启用；不可用时提供具体原因。单层、定位像、SC、缺失/不规则几何、静态体积、时间信息不足分别说明，不展示一个无效空黑视图。
- 空间层号和时间时相分开；2D Cine 有播放/暂停、逐帧、帧率和循环，4D 还需独立时间轴、时相号及时间信息。时间信息缺失时不编造采集间隔。
- 4D 的每一时相分别校验几何；区分动态增强、门控、超声及不同多帧类型，不将所有多帧数据归为 3D+t。其他维度如回波/扩散参数也不能混入时间轴。
- 切换模式保留合理的序列、时相与定位上下文，复位语义明确；标注绑定源图/帧、坐标系及必要时相，不默认传播到其他时相。
- 3D/4D 按需加载和释放时相，执行内存/GPU 预算与降级；不一次常驻整套高分辨率动态体积。
- 真实 4D 验收须核对时相数、每相空间位置/切片数、播放顺序与计时、MPR 定位、标注归属及导出引用；不以动画能播放作为通过标准。
- 当前支持声明保持为实际已验收能力；技术栈存在示例不等于本项目已接入。[Cornerstone 示例目录](https://www.cornerstonejs.org/docs/examples/)
