# 设计基线（docs/design）

> 这个目录解决一个具体问题：**在没有设计资产的项目里，UI 只能"生成啥是啥"**。
> 2026-10-28 之前，唯一的视觉依据是 `ARCHITECTURE.md` §10.1 那段 ASCII 线框，
> 结果是结构对上了、细节全丢：列表项告警徽标、视口四角叠加层、测量面板、浅色主题。

工作区 v2（2026-10-29）以 `ui-spec.md` 开头的覆盖规格为准：新增工具条、可收起面板、专注模式和序列预览；未实现的测量不再常驻。原型可演示工具选择、面板与主题，真实图像操作以应用和验证记录为准。

## 三个文件，三种用途

| 文件 | 回答什么问题 | 谁看 |
| --- | --- | --- |
| [`tokens.md`](./tokens.md) | 颜色/间距/字号/层级**具体是多少**？主题怎么切？ | 写界面的人 |
| [`prototype.html`](./prototype.html) | 长什么样？**能点、能切主题、能看四种状态** | 评审、验收、产品 |
| [`ui-spec.md`](./ui-spec.md) | 每个元素的**数据来源 / 缺失表现 / 状态色 / 文案**是什么？ | 写界面的人 + 评审 |

三者是引用关系，不是三个版本：`prototype.html` 用 `tokens.md` 的值渲染，`ui-spec.md` 描述
`prototype.html` 里每个格子背后的规则。

## 怎么用

```bash
# 直接用浏览器打开，零依赖、离线可用
open docs/design/prototype.html
```

原型右上角有「演示」分段控件，可切换 **正常 / 空态 / 导入中 / 部分失败 / 降级** 五种状态；
顶栏「浅色/深色」按钮切换主题（画布区始终纯黑，这是硬规则）。

## 三条硬约束

1. **没有进 `ui-spec.md` 的界面元素不许进代码。**
   评审时按 `ui-spec.md` 的行逐项打勾；说不清"数据从哪来"的控件一律驳回。
2. **组件里不许出现十六进制色值与魔法字号。**
   一律走 `tokens.md` 定义的 token（`tokens.md` §9 有自检清单）。
3. **改设计先改这三个文件，再改代码。**
   反过来的顺序（先改代码再补文档）会导致原型迅速失真，最后没人信它。
